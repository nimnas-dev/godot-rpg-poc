# Game Feel

게임 규칙을 가리는 장식이 아니라 입력, 결과, 중요도를 즉시 이해하게 하는 감각적 피드백을 만든다. 모든 효과는 목표 감정과 게임플레이 정보를 가져야 한다.

## 작업 절차

1. 개선할 한 가지 상호작용을 선택하고 입력부터 회복까지 프레임 단위로 관찰한다.
2. 목표 감각을 2~3개 형용사로 정의한다. 예: `빠름`, `정확함`, `무거움`.
3. 입력 반응, 시각, 음향, 시간, 카메라, 햅틱의 현재 신호를 목록화한다.
4. 정보 누락과 타이밍 불일치를 먼저 수정한다.
5. 가장 저렴하고 강한 레이어부터 하나씩 추가한다.
6. 반복 상황과 최악의 전투 밀도에서 과잉 피드백을 검사한다.
7. 효과 on/off 비교와 플레이테스트로 개선 여부를 확인한다.

## 핵심 원칙

- 입력 반응성과 판정 명확성을 파티클보다 먼저 해결한다.
- `anticipation -> action -> impact -> recovery`의 시간 구조를 의도적으로 설계한다.
- 공격자, 피격자, 접촉점, UI가 같은 사건을 서로 다른 의미로 중복 전달하지 않게 한다.
- 효과의 강도를 사건의 게임플레이 중요도에 비례시킨다.
- hit-stop, 흔들림, 섬광은 항상 상한과 접근성 옵션을 둔다.
- 반복 효과는 음높이, 샘플, 모양, 회전 등을 제한적으로 변화시키되 의미는 유지한다.
- 연출 때문에 입력이 먹히거나 판정 시점이 보이지 않게 만들지 않는다.
- 모바일에서는 햅틱, 투명 파티클, 화면 해상도, 배터리 비용을 함께 측정한다.

## 피드백 스택 설계

중요 사건마다 다음을 결정한다.

1. 플레이어가 무엇을 알아야 하는가?
2. 언제 알아야 하는가?
3. 얼마나 중요한 사건인가?
4. 어떤 감정을 느껴야 하는가?
5. 동시에 발생할 수 있는 최대 횟수는 얼마인가?

그다음 필요한 레이어만 선택한다.

- 입력: 버퍼링, 취소 규칙, 즉시 자세 변화
- 시각: pose, flash, squash/stretch, directional particles
- 시간: anticipation, hit-stop, recovery, easing
- 카메라: impulse, zoom, framing
- 음향: transient, body, tail, pitch variation, mix priority
- 햅틱: 짧은 확인, 무게감, 위험 경고
- UI: 체력 지연 바, 피해 숫자, 쿨다운 확인
- 세계: decal, 잔해, 흔적처럼 행동의 지속적 결과

세부 조합과 시작값은 [feedback-stacks.md](references/feedback-stacks.md)를 읽는다.

## Godot 구현 규칙

- 효과 설정을 typed Resource profile로 두고 코드에 수치를 흩뿌리지 않는다.
- gameplay event와 presentation effect를 분리한다. 효과가 빠져도 판정 결과가 동일해야 한다.
- 카메라 흔들림은 누적 가능한 impulse로 처리하고 위치를 영구 변경하지 않는다.
- 전역 `Engine.time_scale` 기반 hit-stop은 UI, 타이머, 멀티플레이, 오디오에 미치는 영향을 검토한다.
- 반복 파티클·피해 숫자·사운드는 프로파일링 후 풀링 또는 동시 재생 제한을 적용한다.
- AudioStreamPlayer2D와 audio bus를 사용해 공간감, 우선순위, 볼륨 상한을 관리한다.
- 효과 품질 등급과 `reduced motion`, 진동, 화면 흔들림 옵션을 제공한다.

## 검증 산출물

- 상호작용 이름과 목표 감각
- 입력부터 회복까지의 타임라인
- 적용한 피드백 레이어와 각 정보 역할
- 강도 등급 및 동시 발생 상한
- 접근성·성능 대체 설정
- before/after 캡처 또는 플레이테스트 관찰

감사 및 튜닝 방법은 [tuning-audit.md](references/tuning-audit.md)를 읽는다. 연구 근거와 Godot 문서는 [sources.md](references/sources.md)를 읽는다.

## 금지 사항

- 약한 기본 조작을 화면 흔들림으로 숨기지 않는다.
- 모든 공격에 같은 hit-stop과 카메라 impulse를 적용하지 않는다.
- 화면 전체 섬광, 강한 색수차, 장시간 흔들림을 기본값으로 강제하지 않는다.
- 효과 수를 완성도의 척도로 사용하지 않는다.
- 플레이어가 판정 실패 이유를 알 수 없는 상태에서 연출만 추가하지 않는다.
