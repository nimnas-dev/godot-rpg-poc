# Sources

## Official Godot documentation

- [Resources](https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html) — Resources as typed, Inspector-editable, serialized and shared data containers.
- [Saving games](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html) — groups, FileAccess, JSON and persistence workflow.
- [File paths in Godot projects](https://docs.godotengine.org/en/stable/tutorials/io/data_paths.html) — use `res://` for packaged content and `user://` for writable player data.
- [ResourceLoader](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html) — cached loading, threaded loading and existence checks.
- [Instancing with signals](https://docs.godotengine.org/en/stable/tutorials/scripting/instancing_with_signals.html) — owner-mediated scene instancing and event communication.

## Established design references

- [MDA: A Formal Approach to Game Design and Game Research](https://www.cs.northwestern.edu/~hunicke/MDA.pdf) — connect mechanics to actual play dynamics and desired aesthetics.
- [Game Programming Patterns](https://gameprogrammingpatterns.com/) by Robert Nystrom — state, command, component, observer, event queue, prototype and data locality patterns.
- [Breaking down the metagame design in a mobile RPG](https://www.gamedeveloper.com/design/breaking-down-the-metagame-design-in-a-mobile-rpg) — combat, progression and reward systems are interdependent and benefit from simulation.
- [Defining Loot Tables in ARPG Game Design](https://www.gamedeveloper.com/design/defining-loot-tables-in-arpg-game-design) — item bases, affixes, weighted drops, smart loot and controlled randomization.
- [The Differences Between Random and Randomized Progression](https://www.gamedeveloper.com/design/the-differences-between-random-and-randomized-progression) — preserve player agency and deterministic routes alongside random rewards.
- [Player Controlled Progression](https://www.gamedeveloper.com/design/player-controlled-progression) — visible goals, unlock expectations and player influence over growth.

Use these to derive a project-specific system. Do not copy the economy or progression cadence of another game without validating the intended audience and core fantasy.
